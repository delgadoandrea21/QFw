# Python environment for a host that runs the Qblox digital-twin QPM
# (services/svc_qblox_twin_qpm) with Qblox timing taken live from
# qblox-scheduler (QFW_QBLOX_TWIN_QBLOX_DEVICE).
#
# It is setup/requirements.txt without the IQM client stack, plus
# qblox-scheduler. The two cannot share an environment: iqm-exa-common pins
# ruamel.yaml==0.17.32 and qblox-scheduler 1.x needs ruamel.yaml>=0.18. A host
# built from this file therefore cannot run the IQM QPMs (svc_iqm_qpm, or the
# shim's IQM devices); run those from the standard environment.
#
# The twin itself needs neither: with its default timing, or with durations
# baked into its calibration file (services/svc_qblox_twin_qpm/
# bake_qblox_durations.py), the standard environment is enough.
#
# Install, from the QFw source tree:
#   uv venv /path/to/qfw-qblox-venv
#   source /path/to/qfw-qblox-venv/bin/activate
#   uv pip install -r setup/build-requirements.txt \
#     -r setup/qblox-twin-requirements.txt --override setup/overrides.txt
#
# Keep the lines below the marker equal to setup/requirements.txt without its
# iqm-* lines; tests/test_qblox_twin_requirements.py checks that.

# --- setup/requirements.txt without iqm-* ---
# mqt.core.mlir binds Qiskit's C API per minor release and accepts only the
# 2.5 series, so this pin tracks the Qiskit the MQT compiler was built for.

qiskit_aer==0.17.2
qiskit-algorithms
qiskit-optimization
supermarq

pennylane-qiskit==0.45.1
qiskit-ibm-runtime
# qiskit-ibm-runtime asks for ibm-platform-services>=0.22.6, and iqm-client
# below pins requests==2.32.3 exactly. ibm-platform-services 0.77.0 moved to
# ibm-cloud-sdk-core>=3.24.4, which needs requests>=2.32.4, so the two cannot
# both be satisfied and the resolver walks back down the platform-services
# versions. Without a floor it reaches 0.55.2, the one version in that range
# published as an sdist only, whose build imports pkg_resources without
# declaring setuptools and so fails. This floor keeps the resolution on 0.66.1,
# the version QFw has been building with. It can go once iqm-client stops
# pinning requests to a single version.
ibm-platform-services>=0.59
qiskit_nature
